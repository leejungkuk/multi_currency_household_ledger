# 도메인 규칙 (woni)

금액·환율·카탈로그·에러 흐름의 정본. 헌법(`CLAUDE.md`)은 절대 규칙만 남기고 도메인 상세는 여기에 둔다.

> 출처: 이관 전 `CLAUDE.md` §아키텍처 규칙(2026-09-18) — 아래 6줄은 문장 수정·요약 없이 원문 그대로 옮긴 것이다.

- 금액은 **양수 저장**, 부호는 `transaction_type`(INCOME/EXPENSE)으로 결정한다. 금액 8자리(≤ 99,999,999) 검증(DTO `@Digits`/`@Max`). DB 타입은 금액 `numeric(19,2)`·환율 `numeric(19,6)`(월 합계는 9자리까지). 월 요약 `total` = 순액(`sum(income.krw_amount) − sum(expense.krw_amount)`). 월 리포트 **통화별 소계는 `(currency_code, transaction_type)`로 분리**(수입·지출 미혼합) `sum(original_amount)`, 카테고리별 소계는 `krw_amount` 합. 거래 목록은 `(transaction_date desc, id desc)` 정렬 + 서버 하드 캡(~500).
- **거래 수정/삭제는 MVP 포함**: `PUT /api/v1/ledgers/{id}`(전체 교체, 생성과 동일 필드)·`DELETE /api/v1/ledgers/{id}`. 둘 다 `member_id` 필수 술어 + IDOR 테스트. 외화 수정 시 환율은 생성과 동일하게 `getRateOnOrBefore(transaction_date)`로 **재해석**(applied_rate·rate_base_date·krw_amount 재계산).
- 환율 기준은 **tts**. 매일 **11:05 KST** 수집 후, **백필 윈도우와 동일한 보정창(기본 30일, `exchange.backfill.window-days`가 정본) 안의 외화 거래 중 "그 거래일에 적용 가능한 최신 환율보다 오래된 환율을 쓰는 것"**(`rate_base_date < getRateOnOrBefore(transaction_date).base_date`)을 그 최신 tts로 **재계산**한다. 재계산 시 `applied_rate`·`krw_amount`·**`rate_base_date(→적용 최신일)`** 를 함께 갱신해 **멱등·수렴**하게 유지한다(갱신 후 다음 주기 빠짐). KRW 거래(`rate=1`)·이미 최신 환율인 거래는 불변. **영업일 수집 실패 시 당일 인트라데이 재시도**(다음 성공 수집이 보정창 미정산분 회수). (주의: `transaction_date==오늘 && rate_base_date<오늘`로 좁히면 주말·공휴일 fallback분 + 수집 실패한 영업일 입력분이 영구 동결 → 정합성 위배.)
- "오늘"(KST)은 **`Clock`(`Clock.system(Asia/Seoul)`) 빈 주입으로 단일화** — 도메인/서비스는 `LocalDate.now(clock)`, 테스트는 `Clock.fixed`. 산발 `LocalDate.now(ZoneId)` 금지(재계산 테스트·정합성). 설정용 `GET /api/v1/exchange-rates/status`는 통화별 `{base_date, fetched_at}`·`last_updated`만 노출하고 **fallback-stale 불리언을 넣지 않는다**(fallback-stale은 입력/미리보기 엔드포인트에만).
- 카탈로그는 **시스템 공용 고정 시드**(수정 불가, 표시명 KO/EN, 자산 이모지 없음, PK는 명시 id로 고정)와 **회원 소유 커스텀 카테고리**(`owner_member_id`, `code=CUSTOM`, `id≥10000`)로 구성한다. 디자인 정본 = 지출 13·수입 8·자산 6(플랜 §재설계 리뷰). 지원 통화 **13종**(KRW·USD·EUR·JPY·CNY·GBP·THB·HKD·SGD·IDR·MYR·AUD·NZD) — **정본은 `CurrencyCode` enum**이고 이 목록과 어긋나면 enum을 믿는다. 기준 통화 KRW 고정(v1)이며 KRW는 base라 환율 행이 없어 `exchange_rate` 테이블·iOS 번들 시드에는 **외화 12종**만 쌓인다. **JPY·IDR은 `unit=100`**(100단위당 가격)이라 환산 시 나눈다 — 단 IDR은 100루피아 ≈ 8.7원이 정상이므로 JPY 밴드를 적용해 이상치로 오판하지 마라. CNY는 EximBank가 역외 위안으로만 제공해 **apiCode만 `CNH`**이고 wire/DB 값은 `CNY`다.
- 에러 흐름은 `BusinessException(ErrorCode) → GlobalExceptionHandler → ErrorResponse(code, message, timestamp)`. HTTP 상태는 `ErrorCode.getHttpStatus()`에서 결정. 신규 ErrorCode는 최소화(인증분 `UNAUTHORIZED`/`FORBIDDEN` 등만).
